SECURITY BEST PRACTICES
================================================================================

DO'S ✓
────
✓ Keep service account key in ~/.gcp/
✓ Set file permissions: chmod 600 ~/.gcp/service-account-key.json
✓ Add ~/.gcp/ to .gitignore
✓ Rotate service account keys annually
✓ Use separate service accounts per environment
✓ Enable audit logging in Cloud Logging
✓ Use VPC Service Controls for sensitive data
✓ Set up Cloud Armor for public endpoints
✓ Enable encryption at rest and in transit
✓ Review access logs regularly

DON'TS ✗
───────
✗ Never commit service account keys to Git
✗ Never share service account keys
✗ Never use editor/owner service account in production
✗ Never leave old/unused service accounts active
✗ Never log credentials in error messages
✗ Never hardcode credentials in source code
✗ Never use global IAM roles (use least privilege)
✗ Never disable audit logging
✗ Never store secrets in Cloud Storage unencrypted
✗ Never share GCP console credentials

================================================================================
TROUBLESHOOTING QUICK START
================================================================================

ISSUE: "Permission denied" error

Solution:
  1. Check environment variable: echo $GOOGLE_APPLICATION_CREDENTIALS
  2. Check file exists: ls -la ~/.gcp/service-account-key.json
  3. Check permissions: chmod 600 ~/.gcp/service-account-key.json
  4. Re-authenticate: gcloud auth application-default login
  5. Regenerate key if needed

ISSUE: "BigQuery API not enabled"

Solution:
  gcloud services enable bigquery.googleapis.com --project=YOUR_PROJECT_ID

ISSUE: "Cannot create bucket"

Solution:
  • Verify billing is enabled on your GCP account
  • Check service account has Storage Admin role
  • Check project ID is correct

ISSUE: Slow queries or high costs

Solution:
  • Use partitioned tables (see GCP_ADVANCED_CONFIG.md)
  • Use clustering on frequent filter columns
  • Export old data to Cloud Archive Storage
  • Use BigQuery Slots for predictable costs

ISSUE: Authentication failed

Solution:
  1. Verify project ID: gcloud config list
  2. Re-login: gcloud auth application-default login
  3. Check project exists: gcloud projects list
  4. Set default project: gcloud config set project YOUR_PROJECT_ID

For more troubleshooting: See GCP_ADVANCED_CONFIG.md > Troubleshooting
