1. gcp_client.py (17 KB) - PYTHON MODULE
   Location: /Users/twhite02/Personal/YoureEdge/gcp_client.py
   Status: Production-ready

   WHAT IT IS:
   Complete Python wrapper for BigQuery and Cloud Storage

   CLASSES:
   - BigQueryClient: Query and insert data
   - StorageClient: Upload/download files
   - SportsMLClient: High-level sports ML operations

   KEY METHODS:

   BigQueryClient:
     query(sql)                  - Execute SQL query
     query_to_dataframe(sql)     - Query and get pandas DataFrame
     insert_rows(table_id, rows) - Insert data
     create_table(...)           - Create new table
     get_table_schema(...)       - Get table schema
     list_tables(dataset)        - List tables
     get_table_stats(...)        - Get table statistics

   StorageClient:
     upload_blob(bucket, src, dst)     - Upload file
     download_blob(bucket, src, dst)   - Download file
     list_blobs(bucket, prefix)        - List files
     upload_json(bucket, data, dst)    - Upload dict as JSON
     download_json(bucket, src)        - Download JSON
     get_bucket_stats(bucket)          - Get bucket stats

   SportsMLClient (high-level):
     insert_game(...)            - Insert game record
     insert_prediction(...)      - Insert model prediction
     get_recent_games(sport)     - Get recent games
     get_model_performance(...)  - Get prediction history

   USAGE EXAMPLE:

   from gcp_client import SportsMLClient

   client = SportsMLClient()

   # Insert a game
   client.insert_game(
       game_id="nfl_2024_001",
       sport="NFL",
       game_date="2024-09-15",
       home_team="Kansas City Chiefs",
       away_team="Cincinnati Bengals",
       home_team_id="12",
       away_team_id="5",
       status="scheduled"
   )

   # Get recent games
   games = client.get_recent_games("NFL", limit=10)
   print(games)

   # Insert prediction
   client.insert_prediction(
       prediction_id="pred_001",
       game_id="nfl_2024_001",
       model_id="spread_v1",
       model_version="1.0",
       prediction_type="spread",
       predicted_value=3.5,
       confidence=0.78
   )

WHAT GETS CREATED IN GCP
================================================================================

BigQuery Infrastructure:
   Dataset: sports_data (US region)

   Tables (6 total):
   1. games
      - Schema: 14 fields
      - Description: Game metadata (teams, scores, status)
      - Partitioning: None
      - Size: Scales with data

   2. game_events
      - Schema: 11 fields
      - Description: Play-by-play events
      - Partitioning: Date (created_at)
      - Size: Scales with data

   3. team_stats
      - Schema: 13 fields
      - Description: Team statistics
      - Partitioning: None
      - Size: ~1 MB per sport per season

   4. training_labels
      - Schema: 7 fields
      - Description: Ground truth for ML training
      - Partitioning: None
      - Size: Scales with training data

   5. predictions
      - Schema: 9 fields
      - Description: Model predictions
      - Partitioning: Date (created_at)
      - Size: Scales with predictions

   6. model_metadata
      - Schema: 13 fields
      - Description: Model versioning and info
      - Partitioning: None
      - Size: ~10 KB (model count * 100 bytes)

Cloud Storage Infrastructure:
   Buckets (3 total):

   1. youre-edge-raw-data
      - Purpose: Raw ESPN JSON files
      - Location: US-CENTRAL1
      - Storage Class: STANDARD
      - Lifecycle: Delete after 90 days

   2. youre-edge-models
      - Purpose: Trained ML model artifacts (.pkl files)
      - Location: US-CENTRAL1
      - Storage Class: STANDARD
      - Versioning: Enabled

   3. youre-edge-training-data
      - Purpose: Parquet training files
      - Location: US-CENTRAL1
      - Storage Class: STANDARD
      - Lifecycle: Archive after 30 days, delete after 1 year

Service Account:
   Name: sports-ml-service
   Email: sports-ml-service@[PROJECT_ID].iam.gserviceaccount.com
   Roles: BigQuery Admin, Storage Admin
   Key: ~/.gcp/service-account-key.json (secure, 600 permissions)

================================================================================
SECURITY & BEST PRACTICES
================================================================================

✓ DO:
   - Keep service account key in ~/.gcp/
   - Set file permissions: chmod 600 ~/.gcp/service-account-key.json
   - Add ~/.gcp/ to .gitignore
   - Rotate service account keys annually
   - Use separate service accounts per environment
   - Enable audit logging
   - Use VPC Service Controls for sensitive data
   - Set up Cloud Armor for public endpoints

✗ DON'T:
   - Commit service account keys to Git
   - Share service account keys
   - Use editor service account for production
   - Leave old service accounts active
   - Log credentials in error messages
   - Hardcode credentials in source code
